# WorkBuddy 控制台 (Skill Console)

> 一个本地化的 Agent 工作台：既能**统一管理你的 WorkBuddy 环境**（Skill / 存储 / 对话），又能把零散能力拆成**可复用的「零件」**、再自动**组装成新 Skill**。安装即可在浏览器打开统一控制台。

---

## 如何调用（安装后）

本产品是一个 WorkBuddy Skill，安装后需通过以下任一方式唤起控制台：

1. **与 Skill 对话入口（最常用）**：在 WorkBuddy 主界面打开「与 Skill 对话」，在技能列表中选择 **WorkBuddy 控制台**，即可在对话框输入需求（例如「打开控制台」「管理我的 Skill」「清理存储」）。
2. **自然语言触发**：在任意对话框直接说「打开控制台 / 打开 WorkBuddy 控制台」「管理我的 Skill / 升级某个 Skill」「清理 WorkBuddy 存储 / 看看占了多大空间」「看我的 Agent 构成 / 零件库里有什么」——命中本 Skill 描述即被自动唤起。
3. **技术标识（用于排查 / 高级入口）**：`agent-grocery-workshop`

---

## 一、产品是什么

**WorkBuddy 控制台** = **管控台** + **零件工坊（Skill 组装引擎）**。

- **管控台**：一张零依赖的浏览器控制台，一屏看清你的 Agent 资产全景，并统一管理已装 Skill（健康度 / 升级 / 删除）、空间管理的占用与清理、历史对话的浏览与检索、自动化任务与运行异常。
- **零件工坊**：把已有 Skill / 文档拆成「零件」，再按你的需求自动检索、冲突二选一、依赖补全，拼装成新 Skill；新 Skill 还能自动拆回零件库，越用越满。

它不是又一个聊天框，而是一台让你**看清 Agent 构造、自己造零件、自己组装新能力**的本地机床。

## 二、产品介绍

- **安装即内置控制台**：作为 WorkBuddy 的一个 Skill 安装后，调用即打开浏览器控制台，无需额外搭环境。
- **零外部依赖、纯本地**：前端是单个 HTML，后端是本地轻量服务；数据全部来自对你本机 WorkBuddy 目录的扫描，没有云端数据库、不上传你的内容。
- **可控、可溯源**：任何删除都会先生成总结备份并移入系统回收站（可恢复）；任一生成的 Skill 都能回溯到它由哪些零件组成、被谁使用。
- **三大核心价值**
  - **透明**：一眼看清 Agent 全景——多少个 Skill、谁偏胖、谁有风险、谁和谁重叠。
  - **积累**：组装与拆解互为正反过程，零件库随使用自然丰盈。
  - **可控**：全自动组装 + 完整溯源，过程不黑盒；危险操作有备份与二次确认。

**适用人群**：想统一管理 Skill / 存储 / 对话的 WorkBuddy 用户；想把零散能力沉淀成可复用零件的开发者；想凭一个想法快速造出新 Skill 的创作者。

## 三、功能介绍

控制台左侧导航共 10 个板块：

| 板块 | 说明 |
|---|---|
| **概览** | Agent 资产全景驾驶舱：KPI（已装 Skill 数 / Token 偏胖数 / 近 7·30 天对话数 / 安全警告数 / 功能重叠对数）、健康度环形图、空间管理分布、Token 消耗 TOP5；内嵌「生命周期」三栏：功能重叠检测、安全风险扫描、更新检查。 |
| **Skill 管理** | 已装 Skill 明细表：名称 / 来源 / 安装时间 / 未使用时长 / 使用次数 / Token 消耗 / 风险等级 / 操作。支持按来源与风险筛选、名称 / 来源 / 风险搜索、翻页（每页 10 行）、一键升级、页面内安全删除；「建议删除」筛选已并入「高 / 危」风险 Skill。 |
| **空间管理** | 占用按「日志 / 会话 / 缓存」分类明细，按风险分四级（放心清理 / 谨慎清理 / Skill 目录 / 不可删除）；一键清理，会话类先生成 AI 总结备份再移入回收站；侧边栏实时显示总占用。 |
| **Skill开发** | 查看历史生成记录；点「新建 Skill」描述需求 → 自动检索零件 → 组装 → 生成可安装 Skill → 一键「安装」到 WorkBuddy；每行操作含安装 / 上传 git / 发布 SkillHub / 拆解，组件数可悬停查看并跳转组件管理。 |
| **拆解任务** | 已生成 Skill 自动拆解回填零件的进度看板，展示「组装 → 拆解 → 回填」闭环；拆解产物列展示具体组件名（可点击跳转组件管理）。 |
| **组件管理** | 零件货架：按 6 大类（需求分析 / 方案设计 / 代码开发 / 测试用例 / 依赖工具 / 参考文档）浏览，列表视图 + 分类筛选，支持翻页与反向关联查看（来源 Skill / 同源伙伴均可点击跳转）。 |
| **对话** | ①「WorkBuddy 会话」：左侧按项目 / 会话树浏览，顶部搜索框跨全部历史会话全文检索并高亮命中；②「与 Skill 对话」：选一个已装 Skill 实时问答（需先在设置配置 LLM）。 |
| **异常日志** | 运行异常与错误采样（读 WORKBUDDY_HOME/logs 的 ERROR / CRITICAL / Traceback），便于排查；无日志时展示预置样例。 |
| **工单管理** | 基于飞书多维表格的反馈工单收集：列表查看、工单号查询、一键新建工单弹窗；侧边栏徽章实时显示工单数量。本地控制台可完整提交与查询，静态分享页以只读快照展示并保留数量统计。 |
| **设置** | 主题、后端地址、开发环境信息、LLM、SkillHub 五项配置（详见第六节）。 |

## 四、使用说明

> 本产品所有操作都在浏览器控制台内完成，无需手动执行任何命令行。下面以「问答场景 + 界面操作」说明。

### 4.1 常见问答场景

**问：我想看看一共装了多少个 Skill，有没有安全风险？**
→ 打开控制台，进入 **概览**。顶部 KPI 直接显示「已装 Skill 数 / Token 偏胖数 / 安全警告数 / 功能重叠对数」；下方「🛡️ 安全风险」卡片列出高风险 Skill 及具体发现；「🧬 功能重叠检测」列出功能重复的 Skill 对与重叠百分比。

**问：某个 Skill 不想要了，怎么安全删除？**
→ 进入 **Skill 管理**，找到目标 Skill，点该行右侧 **删除**。系统先生成 AI 总结备份，再把原始目录移入系统回收站（可从回收站恢复），不会直接永久抹除。

**问：WorkBuddy 占用空间太大，怎么清理？**
→ 进入 **空间管理**。顶部四个 KPI 标明「放心清理 / 谨慎清理 / Skill 目录 / 不可删除」的量级。点分类卡片上的 **清理** 或 **谨慎清理**：日志 / 缓存类直接清理；会话类会弹窗让你勾选要删的会话、先生成会话总结备份，再统一移入回收站。

**问：想翻看之前和某个 Skill 的某段对话？**
→ 进入 **对话**，默认在「WorkBuddy 会话」标签：左侧按项目展开会话树，点任一会话右侧即显示渲染后的完整消息；顶部搜索框输入关键词回车，可跨所有历史会话检索，结果高亮命中位置，点结果直接定位。

**问：想和某个 Skill 直接聊天提问？**
→ 在 **对话** 切到「与 Skill 对话」标签，从下方 Skill 列表点选一个，输入框打字发送即可。若提示未配置 LLM，请先到设置里的 LLM 项填写。

**问：有个想法，想自动生成一个 Skill？**
→ 进入 **Skill开发**，点右上角 **新建 Skill**，在弹窗描述需求（目标 / 输入 / 输出 / 约束等），系统自动检索零件库、拼装、生成可安装 Skill；生成后点 **安装** 即装入 WorkBuddy。生成记录里可看它用了哪些零件、当前状态（已生成 / 已安装）。

**问：想看清某个 Skill 由哪些零件构成？**
→ 进入 **组件管理** 浏览零件货架（6 大类），或进入 **拆解任务** 看生成 Skill 拆解回填的零件进度；点零件卡片看详情与反向关联（被哪些 Skill 使用、哪些同源）。

**问：我想提一个反馈 / Bug，怎么提交工单？**
→ 进入 **工单管理**，点右上角 **+ 新建工单**，在弹窗填写用户名、联系方式、类型（问题 / 需求）、问题描述、预期效果，点 **提交**。提交后系统返回工单号（形如 `FB-0007`），请记好该号用于后续查状态。

**问：我之前提的工单处理得怎么样了？**
→ 进入 **工单管理**，在顶部搜索框输入工单号（支持 `FB-0007` / `fb-7` / `7` 形态）回车，或在列表里直接翻找；点任意一行看详情与当前状态（新增 / 已修改 / 已合入 / 关闭 / 拒绝）。若飞书表里加了「处理备注」列，详情也会展示处理人备注。

**问：把控制台分享给别人，对方能在页面上提交工单吗？**
→ 默认分享出去的是 **只读快照页**，对方能看到工单列表与数量，但不能提交（提交会提示改用本地控制台）。要开放公开提交，需要部署一个云端代理并在构建分享页时注入代理地址，详见第八节。

**问：界面太亮 / 太暗？**
→ 进入 **设置 → 外观**，点 **🌙 暗色** 或 **☀️ 亮色** 即时切换。

**问：与 Skill 对话提示「尚未配置 LLM」？**
→ 进入 **设置 → LLM**，填好 Base URL / API Key / Model，点 **💾 保存配置**（可选先点 **🔌 测试连接**），回到对话页即可聊天。

### 4.2 界面操作速览

- **打开控制台**：在 WorkBuddy 中调用「WorkBuddy 控制台」，浏览器即载入控制台首页（概览驾驶舱）。
- **切换板块**：点左侧导航任意一项。
- **筛选与搜索**：在 Skill 管理页用筛选标签 + 搜索框缩小范围，输入即实时过滤并回到第 1 页。
- **翻页**：列表类页面（Skill 管理、Skill开发、工单管理）底部有「⏮ 首页 / ◀ 上一页 / 第 x / n 页 / 下一页 ▶ / 末页 ⏭」，仅一页时自动隐藏。
- **升级 Skill**：在 Skill 管理页点某行 **升级**，控制台联网校验是否有新版本。
- **删除 Skill**：在 Skill 管理页点某行 **删除**，按弹窗确认，系统备份后再移除。
- **检索历史对话**：在对话页「WorkBuddy 会话」标签顶部搜索框输入关键词回车，结果点击即定位。
- **新建并安装 Skill**：在 Skill开发页点 **新建 Skill** → 填需求 → 等生成 → 点 **安装**。
- **提交工单**：在工单管理页点 **+ 新建工单** → 填表单（用户名 / 联系方式 / 类型 / 问题描述 / 预期）→ 点 **提交**，记下返回的工单号（形如 `FB-0007`）用于后续查状态。

### 4.3 工单管理模块

工单管理用于收集用户反馈与 Bug，数据落地在 **飞书多维表格**（用户自有的自建应用凭证，仅存本地 `.env`，不入库）。

- **工单号**：即飞书「序号」字段，由飞书自动生成（前缀 `FB-` + 4 位自增，如 `FB-0007`）；查询时容忍 `FB-0007` / `fb-7` / `7` 多种写法。
- **字段映射**：提交写入用户名 / 联系方式 / 类型（问题 | 需求）/ 问题描述 / 预期；状态由飞书默认「新增」，后续在飞书里流转为「已修改 / 已合入 / 关闭 / 拒绝」。
- **处理备注**：飞书表若手动加一列「处理备注」（text），详情页会自动展示，无需重新部署。
- **两种运行形态**
  - **本地控制台**（有后端）：可完整提交工单、实时查询，侧边栏 `🎫 工单管理` 徽章显示真实工单总数。
  - **静态分享页**（只读快照）：构建时把工单列表快照注入 `window.TICKET_SNAPSHOT`，列表与数量照常展示，但提交按钮会提示「工单提交请使用本地控制台」；要开放公开提交需配置云端代理（见第八节）。
- **联系方式字段**：飞书「联系方式」为 phone 类型，非手机号内容会被自动跳过以保证工单主体必提交成功（仅该字段告警，不影响其它字段）。

## 五、项目架构介绍

**整体形态**：纯文件 + 脚本 + 本地后端，无外部数据库、无云端依赖。

```
<skill-root>/
├── SKILL.md                  # Skill 元信息与说明
├── README.md                 # 本使用手册
├── library/                  # 零件库（持久数据源，按 6 大类子目录组织）
│   ├── requirements/         # 需求分析
│   ├── design/               # 方案设计
│   ├── coding/               # 代码开发
│   ├── tools/                # 依赖工具
│   └── reference/            # 参考文档
├── generations/              # 每次组装产物（manifest + SKILL.md）
├── assets/                   # 控制台静态资源
├── scripts/
│   ├── workshop.py           # 核心库：检索 / 冲突二选一 / 依赖补全 / 反向关联 / 组装
│   ├── dismantle.py          # 解析 SKILL.md 为候选零件
│   ├── assemble.py           # 给定需求输出选用零件
│   ├── seed_initial_parts.py # 初始化种子零件
│   ├── scan_console.py       # 扫描本机 WorkBuddy，生成控制台数据快照（唯一数据聚合实现）
│   ├── feishu_ticket.py      # 工单后端：直连飞书 OpenAPI（tenant_access_token + bitable），读写工单
│   ├── ticket_cloud_proxy.py # 工单公开提交 / 查询云端代理（腾讯云函数 SCF 入口），凭证走环境变量
│   ├── build_static.py       # 生成只读分享页：刷新快照 → 复制资源 → 注入 STATIC_MODE / TICKET_SNAPSHOT
│   └── server.py             # 管控台本地后端（快照 / Skill 增删 / 对话代理 / 搜索 / 生成安装 / 工单 等接口）
├── console.html              # 管控台前端（单文件、零依赖，可离线打开）
├── console_data.json         # 本机扫描快照
├── console_config.json       # 本地配置（含 LLM / SkillHub 密钥，不入库）
└── start_console.bat / .ps1  # 启动脚本
```

**数据 / 视图解耦**：`library/` 与 `generations/` 是唯一持久数据源；`console.html` 只是视图，由扫描程序把最新数据注入快照，重新生成不会丢失零件或生成记录。`shop.html` 为早期解剖图视图（其生成脚本 `generate_shop.py` 已移除），功能已并入控制台「组件管理 / Skill开发 / 拆解任务」，现已不再生成。

工单数据持久化在 **飞书多维表格**（非本地文件），由 `feishu_ticket.py` 直连飞书 OpenAPI 读写；`deploy_static/`（分享页构建产物）、`console_data.json`、`.env` 按 `.gitignore` 不入库，分享前需重新构建。

**前后端协作**：前端 `console.html` 通过浏览器请求本地后端获取实时数据（Skill 增删、对话代理、历史检索、生成安装等）；离线打开时读取已内联的快照，部分需后端的实时功能会受限。

**积累闭环**：组装生成新 Skill → 自动拆解回零件库 → 零件库更丰富 → 下次组装检索命中更多。

## 六、设置页面 —— 每项配置说明

进入 **设置** 板块，自上而下共五组配置：

### 1. 外观（🎨）
- **暗色 / 亮色**：二选一切换界面主题，点击即时生效，选择保存在浏览器本地。
- 用途：适配当前系统环境或个人观感。

### 2. 控制台后端（🖥️）
- **后端地址**：控制台前端访问后端 API 的地址，默认指向本机默认端口。仅当后端不在默认地址（如改过端口）时才需要改。
- 该值仅保存在浏览器本地，**不写入任何文件**；若改错导致连不上后端，把地址恢复为默认或留空即可。

### 3. 开发环境（🧰）
- **扫描根目录**：当前被扫描的 WorkBuddy 家目录，由扫描程序自动识别，仅展示、不可编辑。
- **Python 路径**：后端运行所用的解释器路径，自动识别，仅展示、不可编辑。
- 用于确认控制台正在扫描正确的环境，无需手动干预。

### 4. LLM（🤖）
用于「对话 → 与 Skill 对话」页与 Skill 实时交流。
- **Base URL**：大模型接口地址（OpenAI 兼容格式）。
- **API Key**：该接口对应的密钥。
- **Model**：模型名称（如 `gpt-4o` 等）。
- **🔌 测试连接**：保存前后都可点，向该接口发一条测试消息验证连通性与密钥有效性。
- **💾 保存配置**：把以上三项写入本地 `console_config.json`，同时缓存到浏览器供对话页使用。未配置时，与 Skill 对话会提示「尚未配置 LLM」。

### 5. SkillHub（🛒）
用于「Skill 管理」的升级校验与版本检查。
- **SkillHub Base URL**：检查已装 Skill 是否有新版本的接口地址。
- **API Key（可选）**：公开接口通常无需填写；私有部署时才填。
- 保存后，Skill 管理页的「升级」会据此联网比对版本。

> 注：LLM 与 SkillHub 的密钥保存在本地配置文件中（不入库、不随 Skill 分发）；后端地址仅存于浏览器本地。请妥善保管本地配置文件。

## 七、常见问题（FAQ）

**Q：控制台连不上后端怎么办？**
A：看页面右上角状态灯——显示「后端未连接」时，点它跳到「设置 → 控制台后端」，确认后端地址正确（默认本机端口），或把地址留空恢复默认。

**Q：删除的 Skill 还能找回吗？**
A：能。删除走的是「总结备份 + 系统回收站」，原始目录在回收站里，可从回收站恢复。

**Q：清理存储会误删我的 Skill 吗？**
A：不会。空间管理只清理日志 / 会话 / 缓存类目录；Skill 目录被标记为「不可删除」，清理按钮不会出现。

**Q：生成的 Skill 保存在哪？**
A：在 `generations/` 数据目录，并可在控制台「Skill开发」记录里查看；点「安装」后才会装入 WorkBuddy 的 skills 目录。

**Q：换台机器，零件库会丢吗？**
A：`library/` 与 `generations/` 是普通文件，随 Skill 目录一起迁移即可；控制台视图由扫描程序重新生成，不依赖旧快照。

**Q：工单号是什么？在哪里查？**
A：工单号即飞书「序号」字段，提交后系统返回（形如 `FB-0007`）。进入「工单管理」顶部搜索框输入该号（也支持 `fb-7` / `7`），或直接在列表里翻找，点行看详情与状态。

**Q：为什么分享出去的页面不能提交工单 / 看不到最新数据？**
A：分享页是只读快照，数据在构建那一刻冻结；提交工单需连本地后端或云端代理。要开放公开提交，请部署工单云代理并注入 `TICKET_API_BASE` 后重新构建（见第八节）。查看实时数据请用本地控制台。

**Q：怎么生成给别人看的分享链接？**
A：运行 `python3 scripts/build_static.py` 生成 `deploy_static/`，再用 `workbuddy_cloudstudio_deploy` 部署即可；沙箱链接有时效，过期需重新构建部署。

## 八、静态分享页（用于对外分享的只读快照）

想把控制台页面发给他人查看时，可构建一个**无需后端、纯静态**的只读快照页，部署到云端沙箱得到一个公开链接。

**适用场景**：展示 Agent 资产全景、Skill / 组件 / 工单等列表数据；**不支持**拆解、安装、生成、提交工单等需要写后端的操作。

**构建步骤**：
1. 在本机确保后端与扫描已就绪（已运行 `python3 scripts/server.py` 并完成一次扫描）；工单数据如需带入快照，请先在本机后端执行过工单相关操作。
2. 运行 `python3 scripts/build_static.py`：依次刷新 workshop / storage 快照、复制 `assets/`、`console_data.json`，并注入 `window.STATIC_MODE = true` 与 `window.TICKET_SNAPSHOT`（工单列表快照）。产物在 `deploy_static/`。
3. 用 `workbuddy_cloudstudio_deploy`（directory=deploy_static, entry=index.html）部署到 CloudStudio 沙箱，得到公开链接 `https://<id>.app.workbuddy.link`。

**注意事项**：
- `deploy_static/`、`console_data.json`、`.env` 已在 `.gitignore`，**不随代码提交**，每次分享前需重新构建。
- 静态页右上角状态灯会显示「后端未连接」，属正常（只读页本就无后端）；空间管理、工单等页面会自动改用快照数据展示，不再发起实时请求。
- 要开放**公开提交工单**，需单独部署 `scripts/ticket_cloud_proxy.py`（腾讯云函数 SCF）并把函数 URL 注入 `window.TICKET_API_BASE` 后重新构建分享页；否则分享页工单提交会提示改用本地控制台。
